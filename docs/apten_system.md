# APTEN System

## Identity
APTEN does not accept the rules of combat; it modifies them. It specializes in control, hacking, rule manipulation, and state manipulation.

## Mechanics

### COMPROMISED
`COMPROMISED` is a temporary relationship between a **Source Bot** and a **Target Bot**. It is not a global debuff.

- **Source Ownership**: Only the source that applied the mark can read, exploit, refresh, or consume it. Allies cannot exploit another bot's mark.
- **Coexistence**: Multiple sources can independently apply Compromised to the same target (e.g. `Source A -> Target X`, `Source B -> Target X`).
- **Refresh**: Reapplying Compromised from the same source to the same target refreshes the duration; it does not stack.
- **Consumption**: Abilities that "Consume Compromised" must only clear the mark if the enhanced effect actually succeeds.
- **Neutrality**: By itself, Compromised has no inherent effect (no damage, no slow, no armor reduction). Its effect comes entirely from interactions with specific APTEN abilities.
- **Architecture**: Managed by the lightweight `AptenStatusController` added dynamically to actors. Uses `source_instance_id` and weakrefs to guarantee memory safety even if the source is destroyed.

### Movement Taxonomy (Traversal vs Discrete Relocation)
To support future mechanics (like Quarantine Gate), movement abilities are classified by their semantic physical behavior.

**Traversal** (Physically travels through intermediate space):
- Space Dash
- Charger Charge
- Tank Siege Drive
- Vector Strafe
- Rocket Lunge
- Assassin Recoil Step

**Discrete Relocation** (Teleports instantly from A to B without occupying intermediate space):
- Light Phase Blink
- Vector Anchor (Return teleport)

*Future Rule*: Quarantine Gates will only trigger if an actor physically *traverses* the gate boundary. True relocations (teleports) bypass it entirely. Line-intersection faking must not be used to punish relocations.

### Qualified Hit Readiness
Multi-projectile or multi-hit abilities (e.g., Twin Stream, Burst Volley, Shotguns) generate multiple independent damage events. To support mechanics that require "qualified hits" (e.g., "trigger after 3 attacks"), the combat engine assigns a single `attack_event_id` to all projectiles or melee swings generated by a single ability activation or trigger pull. This metadata propagates to the damage event, allowing future systems to correctly group simultaneous projectiles as a single unified attack.
